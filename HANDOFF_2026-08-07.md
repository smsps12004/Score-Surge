## What shipped today

Three commits, all pushed: `cf21af4`, `b6af716`, and `33110e8` (the evening
work below). The edge function is deployed separately via the Supabase dashboard
and is live.

**Cancellations no longer leak.** The webhook handled exactly one event —
`checkout.session.completed` — so a sailor who cancelled, or whose card died,
kept Chief access forever. It now also handles `customer.subscription.updated`
and `customer.subscription.deleted`, and sets the tier to whatever the
subscription currently entitles them to.

One deliberate judgment call: `past_due` still counts as entitled. When a card
fails Stripe retries for days before giving up; cutting a sailor off on the first
failed charge takes access away mid-study from someone who is about to pay
successfully. Access ends at `canceled` or `unpaid` — when Stripe has actually
stopped trying. A cancellation scheduled for period end arrives as an `active`
subscription with `cancel_at_period_end`, so they correctly keep access until the
day it really ends.

**Profiles now carry `stripe_customer_id`** (new nullable text column). Checkout
records it; every later subscription event matches on it instead of on email.
Two reasons this matters:

- Email matching was fragile. Apple Pay can supply a different address than the
  account's — the 7 Aug test only worked because `create_checkout_session` passes
  `customer_email`, which locks it. Customer id has no such failure mode.
- **It protects hand-set accounts.** Shawn's own profile is `chief` because it was
  set directly in Supabase, with no Stripe subscription behind it. It has no
  customer id, so no Stripe event can reach it. Under email matching a stray event
  could have demoted him.

**A silent failure is no longer silent.** The webhook's update ran without
checking whether it matched anything, so "no profile with that email" returned
`200 OK` — Stripe showed green while a paying sailor sat locked out. A paid
checkout that upgrades nobody now returns 500, so Stripe retries and it is
visible. Subscription events that match nothing still return 200, because an
unlinked customer genuinely is a no-op.

**Error 42501 fixed.** Supabase was refusing every score write under row-level
security. Streamlit re-executes the whole file per interaction and `create_client`
returns a fresh anonymous client each time, but the session restore was guarded by
`and not st.session_state.user` — true only on the first pass. Every later call

the Chief points at the governing manual instead of judging a sailor against a key
nobody vouched for. Generation rules tightened against all three failure modes.

**Entitlement hardened.** `get_user_tier` used `.single()`, which raises both on
"no row" and on a network blip, and one branch handled both — so one hiccup took a
paying sailor, wrote a profile row, and showed them "free" with paid tabs locked.
It now tells the cases apart, retries once, and writes nothing when it cannot find
out. New profiles are created with an email (the webhook matches on it) and get the
trial the signup screen promises even when Supabase withholds a session for email

**Score history is readable.** The interactive Vega line chart is gone — with two
